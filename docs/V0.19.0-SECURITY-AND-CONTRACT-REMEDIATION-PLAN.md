# v0.19.0 security and contract remediation plan

**Status:** in progress  
**Scope:** confirmed 2026-11-02 follow-up audit of evaluator isolation, packet drift enforcement, Core input/Runtime/GitHub contracts, generated-packet synchronization, secret handling, bounded clients, workflows, MCP, catalog integrity, and user documentation.

This plan treats an audit finding as complete only when the implementation, focused regression coverage, generated packets, documentation (where applicable), local deterministic gate, and hosted matrix evidence agree. It does not weaken supported Node 22, portable suites, or deterministic evaluation requirements.

## Wave 1 — untrusted execution and network/HTTP boundaries

- [x] **S1 Outcome evaluator filesystem containment**
  - [x] Apply Node Permission Model read/write constraints to every child that runs workspace-controlled source: syntax, tests, copied `spec-check`, and copied gate runner.
  - [x] Fail closed for live/untrusted evaluation runners when no filesystem permission boundary is available; retain deterministic trusted-fixture calibration compatibility at the published Node floor.
  - [x] Avoid test-runner child-process permission by execute-testing each `node:test` module in the bounded process; the generated gate runner receives an evaluator-only already-checked drift handoff rather than child-process permission.
  - [x] Add an escape-write regression and assert no external sentinel changes.
- [x] **S2 Runtime over-limit HTTP contract**
  - [x] Drain/ignore remaining input after crossing the 64 KiB limit without destroying the socket before the response.
  - [x] Return a JSON `413 RUNTIME_REQUEST_TOO_LARGE` envelope deterministically.
  - [x] Cover chunked over-limit bodies.
- [x] **S3 Bounded Runtime response readers**
  - [x] Centralize a streaming, byte-counted Runtime JSON response reader.
  - [x] Use the same streaming byte-limit contract in Core client, browser Studio, and VS Code Studio (browser/extension stay dependency-free).
  - [x] Cover missing content length and chunked oversized responses.

## Wave 2 — fail-closed policy and forge contracts

- [x] **C1 Profile root/nested-shape validation**
  - [x] Reject null/non-object roots and wrong types for policy-bearing containers before normalization.
  - [x] Preserve usage error semantics (CLI exit 2) instead of exposing raw `TypeError`.
  - [x] Cover null roots, scalar `traits`/`overlays`, malformed nested objects, and valid arrays.
- [x] **C2 GitHub immutable preflight identity**
  - [x] Accept a check only when `head_sha` is exactly the reviewed `plan.headSha`.
  - [x] Reject missing/stale identities and hostile/foreign pagination links.
  - [x] Update all check fixtures to include exact SHA identity.
- [x] **C3 Catalog payload byte binding**
  - [x] Hash the original `Buffer` for manifest/index/payload digests that promise blob-byte identity.
  - [x] Preserve raw-byte copies and add invalid-UTF-8 substitution regression coverage.

## Wave 3 — deterministic packets and semantic evidence

- [x] **P1 Shared recursive packet-sync command**
  - [x] Implement one reusable compiler-to-temp-directory recursive comparison script.
  - [x] Invoke it from `npm run check` and CI for self-spec and example packets.
  - [x] Cover stale nested enforcement assets in distribution tests.
- [x] **P2 Semantic-drift ratchet**
  - [x] Extend G3 mutation metadata and its generated runner with a required, separately located semantic-oracle manifest: every automated requirement needs an `@req`-anchored assertion test under `tests/semantic-oracles/` in addition to mutation-tool configuration.
  - [x] Make the outcome probe run an evaluator-owned functional oracle and separately report local-test, functional-oracle, and controlled-mutant-identity coverage. The latter detects the known calibration mutant even when implementation and local tests are co-mutated; it is explicitly not represented as a project test kill score.
  - [x] Add positive/negative runner tests and calibration ratchets: vld-packet semantic detection is 24/24, local structural semantic detection remains separately reported as 0/24.
- [x] **P3 Secret scanning and history coverage**
  - [x] Scan every regular, non-binary repository file outside packet/delta exclusions rather than an extension allow-list or skipped product directories.
  - [x] Wire a pinned, bounded gitleaks history scan in deterministic CI with a full-history checkout.
  - [x] Add fixtures for uncommon file names and formerly excluded directories.

## Wave 4 — explicit unsafe capability and bounded execution

- [x] **E1 Routing `cmd` driver acknowledgement**
  - [x] Require `--unsafe-command` / `unsafeCommandAcknowledged` before command execution.
  - [x] Scrub inherited environment and preserve timeout/output limits.
  - [x] Verify deterministic workflow does not pass the acknowledgement and test provider-secret scrubbing.
- [x] **E2 Workflow command timeout receipts**
  - [x] Set a bounded subprocess timeout.
  - [x] Persist a typed timeout failure receipt with bounded digest evidence.
  - [x] Cover a timed-out command stub.

## Wave 5 — protocol conformance and documentation

- [x] **D1 MCP/Runtime HTTP conformance**
  - [x] Enforce required `tier` and string primitive IDs from advertised MCP schemas.
  - [x] Treat id-less JSON-RPC tool calls as notifications (no response).
  - [x] Cover catalog projection, OPTIONS, 404, unsupported methods, recovery/heartbeat, and body-limit Runtime paths.
- [x] **D2 Release and command documentation**
  - [x] Publish concise v0.19.0 release notes and make roadmap material future-facing.
  - [x] Generate `docs/CLI.md` from CLI usage rather than duplicate command prose.
  - [x] Generate/verify practice and test inventory counts; archive completed audit plans so historical counts are not current guidance.
