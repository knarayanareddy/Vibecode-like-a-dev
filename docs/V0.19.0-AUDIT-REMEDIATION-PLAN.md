# v0.19.0 Audit Remediation Plan

**Status:** In progress
**Decision:** Treat the confirmed audit findings as the next delivery phase before expanding Public Web Discoverability beyond its deterministic Phase 1 compiler boundary. The next discoverability capability (a human-authored readiness artifact) is valuable, but it must not distract from Runtime authority, evaluator isolation, persistence, and validation correctness.

## Delivery order

1. **Audit Wave 1 — fail-closed trust and compiler correctness (P0/P1):** items 1–9, plus their regression tests.
2. **Audit Wave 2 — public contracts and bounded transports (P2):** items 10–14.
3. **Audit Wave 3 — maintenance, documentation, and diagnostics (P3):** items 15–18.
4. **Public Web Discoverability Phase 2:** only after Waves 1–2 are green; it will add a human-reviewed readiness artifact without a crawler, network client, credential, ranking, or provider authority claim.

## Remediation checklist

### Wave 1 — trust and compiler correctness

#### 1. Runtime external-authority boundary

- [x] Mark every forge/runtime receipt exported by Core as `local-ledger` evidence, not GitHub, PR, merge, branch-protection, or CI proof.
- [x] Ensure generated plans and user documentation say that a provider adapter is a separate optional boundary; Core does not dereference remote state.
- [x] Add tests that reject/flag claims of remote authority where only local evidence exists.
- [ ] **Acceptance:** a consumer cannot reasonably interpret a Core receipt tuple as external delivery attestation.

#### 2. Ordered overlays and change archive atomicity/history

- [x] Validate each overlay against the catalog state resulting from preceding overlays, then apply it in layer order.
- [x] Keep provenance additions/removals consistent with final ordered effects.
- [x] Stage overlay/profile/archive/history changes, recompile/validate against staged inputs, then atomically promote; on failure preserve the original profile, packet, overlay, archive, and history.
- [x] Persist retired requirement IDs across archive history rather than only the active packet.
- [x] Add cross-overlay target, recompile failure rollback, add-then-remove provenance, and historical-ID regression fixtures.
- [x] **Acceptance:** an overlay can target an earlier overlay’s addition, while any failed archive is observationally and byte-wise non-mutating.

#### 3. Outcome evaluator execution boundary

- [x] Scrub child-process environments to an explicit minimal allowlist and never pass host credentials to workspace checks.
- [x] Run untrusted workspace checks/oracles in a separate Node process with an explicit workspace-only permission boundary where supported; never dynamically import workspace code into the harness process.
- [x] Make arbitrary `cmd` runners explicitly unsafe/opt-in and document that a same-user command is not an OS sandbox; do not use it in ordinary validation or CI.
- [x] Keep direct-model responses constrained to validated relative files, bounded file counts/sizes, and process-separated evaluation.
- [x] Add hostile-workspace tests for environment secrecy, parent-harness preservation, traversal rejection, and unsafe-command opt-in.
- [x] **Acceptance:** default/calibration evaluation has no in-process untrusted module import or ambient-secret inheritance; arbitrary command execution is impossible without an explicit unsafe acknowledgment.

#### 4. Adoption schema signal detector

- [x] Replace the truthy RegExp callback with `.test(file)`.
- [x] Add positive and negative repository fixtures.
- [ ] **Acceptance:** only files whose names actually contain `model`, `entity`, or `schema` create schema-signal evidence.

#### 5. Drift guard parity

- [x] Replace single three-digit, same-line anchor matching with global `REQ-<three-or-more digits>` extraction in both `verify` and generated `spec-check`.
- [ ] Support a documented immediate preceding-line marker association, multiple IDs, and matching suppression behavior. (Multiple IDs and suppression are implemented; preceding-line association is intentionally not a supported documented form.)
- [ ] Share or mirror EARS vague-response enforcement and assertion-density semantics; generated EARS vague-response enforcement is now aligned, while assertion-density parity remains.
- [ ] Add parity fixtures and an emitted-guard execution test.
- [ ] **Acceptance:** the CLI verifier and the shipped guard report the same anchor/EARS/assertion verdict for a representative fixture suite.

#### 6. Final-destination filesystem safety

- [ ] Add a shared safe-final-file helper that walks existing parents with `lstat`, rejects final symlinks including dangling links, and writes through an atomic sibling file where overwrite is supported.
- [ ] Apply it to artifacts, exports, change archives/backups/history, store/catalog copied payloads, and other audited write sinks.
- [ ] Add Unix symlink fixtures for final dangling links and intermediate links; keep Windows-safe behavior covered by portable tests.
- [ ] **Acceptance:** no destructive write/copy follows an intermediate or final link outside its intended root.

#### 7. GitHub preflight authority

- [x] Page reviews and check runs to bounded exhaustion, require reviews for the exact planned head SHA, and deduplicate to each check name’s latest attempt.
- [x] Reject stale success when a later/current failure, pending run, missing check, or wrong SHA exists.
- [x] Add mocked multi-page, stale-review, stale-success/new-pending rerun fixtures.
- [x] **Acceptance:** a forge plan is refused unless every required approval/check is current for the immutable planned head.

#### 8. Secret-placeholder allowance

- [x] Replace line-wide exception matching with exact value/token recognition limited to deliberate fixture syntax.
- [x] Keep realistic test fixture secrets detectable when unrelated prose on the same line says `example`, contains `<`, or uses ellipses.
- [x] Add positive/negative scanner tests.
- [ ] **Acceptance:** only the intentionally recognized placeholder itself is allowed; neighboring credential-shaped text is still rejected.

#### 9. Requirement anchors

- [x] Complete the shared anchor implementation in item 5 and update authoring/README examples to the documented same-line form.
- [ ] Add IDs at and beyond `REQ-1000`, several IDs on one line, source-only markers, and preceding-line behavior to tests. (The high-ID/multiple/source-only coverage is present; preceding-line association remains deliberately unsupported.)
- [ ] **Acceptance:** all documented marker forms are deterministically scanned exactly once.

### Wave 2 — public contracts and bounded transports

#### 10. Emitter/MCP alignment

- [ ] Derive suggested test-anchor extension, fenced-language label, selected-practice wording, and aggregate primitive hints from one normalized stack/plan model.
- [ ] Remove obsolete primitive identifiers and conditionalize generated prose on selected practices.
- [ ] Add stack matrix and MCP/packet snapshot parity tests.

#### 11. CLI and Runtime client contract

- [ ] Make `store init` positional/`--id` semantics unambiguous in parser, help, and tests.
- [ ] Define an explicit optional remote Runtime client endpoint/base URL and use typed request/response validation rather than local-only assumptions.
- [ ] Define initial allocation idempotency without requiring a token that does not yet exist; preserve token requirements for retries/mutations.
- [ ] Add local/remote client parity tests and invalid-option tests.

#### 12. Runtime event history

- [ ] Label the current state event window as `recentEvents`, never full history.
- [ ] Add a bounded cursor/pagination API for durable ledger events with authorization and byte/count limits.
- [ ] Update Studio to state whether it is displaying recent or paged historic receipt evidence.
- [ ] Add truncation and pagination tests.

#### 13. MCP JSON-RPC boundary

- [x] Validate object-only JSON-RPC envelopes and parameter types before dispatch; use `-32600`/`-32602` consistently.
- [x] Reject rather than coerce malformed numeric controls.
- [x] Bound stdin request-line and aggregate-buffer sizes; fail one malformed/oversized request without crashing the session.
- [ ] Add array/null/non-object, bad numeric, oversized, and recovery tests. (Envelope and numeric coverage is present; oversize/recovery transport fixtures remain.)

#### 14. VS Code response bounds

- [x] Enforce a response-byte ceiling while streaming `runtimeStatus`; destroy/reject oversize responses before concatenation.
- [x] Bound JSON parsing/display payloads and add a test server fixture for a large response.

### Wave 3 — maintenance and clarity

#### 15. CI/package maintenance

- [x] Add a least-privilege Dependabot configuration for npm and GitHub Actions.
- [x] Add explicit bounded job timeouts around potentially long tooling; keep existing action SHAs pinned and document upgrade review.
- [x] Add static tests for the maintenance contract.

#### 16. Regression coverage

- [ ] Add every Wave 1–2 adversarial fixture to the ordinary Node test suite and retain the relevant Windows/macOS portable lane coverage.
- [ ] Make the historical audit findings traceable to tests without claiming a test proves external-provider truth.

#### 17. Documentation coherence

- [x] Make AUTHORING front-matter examples parsable by the actual flat parser or document/implement a safe nested parser.
- [ ] Align body-contract, EARS, anchor, tier-budget, counts, roadmap/version language, and generated statistics with enforced behavior. (Anchor/tier-budget corrections are in; remaining historical/generated-statistic cleanup is queued.)
- [ ] Prefer generated/checked facts over manually maintained inventory counts.

#### 18. Safe diagnostics

- [ ] Centralize safe subprocess/remote error summaries; do not interpolate host paths, raw remotes, or arbitrary stderr into normal user-facing messages.
- [ ] Provide an explicit local debug mode for bounded diagnostic detail.
- [ ] Add redaction/path-leak tests for Git and catalog errors.

## Phase 2 public-web readiness gate

- [ ] Wave 1 and Wave 2 checks are green locally and in all supported hosted lanes.
- [ ] Public-web Phase 1 remains byte-compatible for absent/disallowed profiles.
- [ ] The Phase 2 artifact remains human-authored/reviewed and locally verifiable; it must not introduce a crawler, search-provider API, browser dependency, credentials, or ranking/citation authority.
