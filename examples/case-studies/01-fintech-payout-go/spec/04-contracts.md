## 3. Conventions that bind you

Only the conventions this profile makes load-bearing are listed. The selected-practice table in 00-constitution.md names every additional obligation this packet actually selected; no unselected library practice is implied.

| Concern | Rule |
| --- | --- |
| Identifiers | Every settlement id is opaque and sortable (ULID); a sequential integer never appears in an external shape, because it invites enumeration. |
| Timestamps | Instants on a settlement are ISO-8601 UTC with `Z`; a local time or a bare date is a bug, not a style choice. |
| Money | Integer minor units plus an ISO-4217 code. Never a float, never a pre-formatted string. |
| Idempotency | Every mutation that can move money takes an `Idempotency-Key`; a replay returns the first result, never a second settlement. |
| Tenant | Derived from the authenticated session, never from a body field or a query parameter. |
| Errors | One envelope for every failure — including an unknown route and a rejected settlement — and an absent field is absent, not `null`. |

## 4. Error envelope

One shape for every failure. A caller must be able to handle an unknown route with the same code as a rejected input.

```json
{
  "error": {
    "code": "PAYMENT_DECLINED",
    "message": "The card was declined by the issuer.",
    "correlationId": "01J8Z9W3Q4K5M6N7P8R9S0T1V2",
    "details": [
      {
        "field": "merchant",
        "reason": "conflict"
      }
    ]
  }
}
```

| Status | Meaning | When |
| --- | --- | --- |
| 401 | No valid session | Missing, expired or revoked credential. No settlement is created and no state changes. |
| 403 | Authenticated but not permitted | Policy denied for this merchant. Never reveal whether the settlement exists. |
| 404 | Not found, or not visible to this actor | One response for both cases, so a settlement id cannot be used to probe. |
| 409 | Conflict with current state | The settlement would be left in a state `02-domain-model.md` calls illegal, or a replay carries a different payload. |
| 422 | Semantically invalid | Well-formed but breaks a rule that makes a settlement valid. |
| 429 | Rate or quota limited | Includes `Retry-After` and performs no work. |

## 5. Contract tests

- Each of the 5 surfaces gets one test for its success shape and one for the settlement failure it is most likely to hit.
- Anything this product consumes is tested against a recorded response; a hand-written mock of a merchant drifts silently.
- Changing a shape in section 2 fails the build before review, because the test that pins it lives beside the settlement it serialises.

Before implementing any row above: shape written, error code chosen, one failure example recorded.
