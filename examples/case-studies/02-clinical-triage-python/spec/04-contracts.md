## 3. Conventions that bind you

Only the conventions this profile makes load-bearing are listed. The selected-practice table in 00-constitution.md names every additional obligation this packet actually selected; no unselected library practice is implied.

| Concern | Rule |
| --- | --- |
| Identifiers | Every disposition id is opaque and sortable (ULID); a sequential integer never appears in an external shape, because it invites enumeration. |
| Timestamps | Instants on a disposition are ISO-8601 UTC with `Z`; a local time or a bare date is a bug, not a style choice. |
| Tenant | Derived from the authenticated session, never from a body field or a query parameter. |
| Model I/O | Input and output are declared schemas; a malformed completion is a rejection, never a partial write. |
| Errors | One envelope for every failure — including an unknown route and a rejected disposition — and an absent field is absent, not `null`. |

## 4. Error envelope

One shape for every failure. A caller must be able to handle an unknown route with the same code as a rejected input.

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "The disposition is not in a state that allows this.",
    "correlationId": "01J8Z9W3Q4K5M6N7P8R9S0T1V2",
    "details": [
      {
        "field": "patient",
        "reason": "conflict"
      }
    ]
  }
}
```

| Status | Meaning | When |
| --- | --- | --- |
| 401 | No valid session | Missing, expired or revoked credential. No disposition is created and no state changes. |
| 403 | Authenticated but not permitted | Policy denied for this patient. Never reveal whether the disposition exists. |
| 404 | Not found, or not visible to this actor | One response for both cases, so a disposition id cannot be used to probe. |
| 409 | Conflict with current state | The disposition would be left in a state `02-domain-model.md` calls illegal, or a replay carries a different payload. |
| 422 | Semantically invalid | Well-formed but breaks a rule that makes a disposition valid. |
| 429 | Rate or quota limited | Includes `Retry-After` and performs no work. |

## 5. Contract tests

- Each of the 4 surfaces gets one test for its success shape and one for the disposition failure it is most likely to hit.
- Anything this product consumes is tested against a recorded response; a hand-written mock of a patient drifts silently.
- Changing a shape in section 2 fails the build before review, because the test that pins it lives beside the disposition it serialises.

Before implementing any row above: shape written, error code chosen, one failure example recorded.
