## 1. The laws, and what they mean here

The left column is law for every project this factory compiles. The right column is what that law obliges here — when the two seem to conflict, the right column is wrong and belongs back in the compiler.

| Law | In Vibecode Like A Dev |
| --- | --- |
| The spec is the interface. | A change to how an agent behaves starts as a change to a requirement or an ADR — never as a code edit the spec is later bent to match. |
| A failing test comes before behaviour. | 3 of 6 requirements are proven by a test carrying `@req`; the rest carry a manual script. Untested behaviour is proposed, not done. |
| One term, one meaning. | `agent` and `specification` are the only names for those things — in code, in tests, in commit messages, and in the UI copy specifications read. |
| Boundaries before bodies. | The 1 surfaces in `04-contracts.md` are fixed while changing them is free; after sign-off, a change to one needs its own requirement. |
| The domain stays pure. | Rules import no framework, no PostgreSQL, and no vendor SDK. Hexagonal single artifact only holds if this is checked, not intended. |
| Boring technology, justified additions. | 17 practices were selected for Vibecode Like A Dev; anything not among them needs an ADR naming what it replaces and what breaks without it. |
| Fail closed. | Deny by default for authorization; refuse rather than guess; never silently weaken a control to make a test pass. |
| Make it observable. | A failed agent operation is a log line with a correlation id and the specification it belonged to — including the ones you think cannot happen. |
| Reversible beats predictable. | Schema changes go forward only, behind a PostgreSQL migration; 8-week scope means something gets cut, so cut features, not rollback paths. |
| Stop and ask before guessing. | Three failed attempts on REQ-001 means the model of the problem is wrong. Escalate with what you tried and what you ruled out. |

## 2. Definition of done

An agent change is done when all of the following are true for Vibecode Like A Dev. Not "mostly true".

- [ ] **G0-RUN** — The project starts from a clean clone with one documented command. _Here: for Vibecode Like A Dev: one command, and a missing variable is named._
- [ ] **G0-CHECK** — Lint or typecheck runs in CI on every pull request.
- [ ] **G0-SMOKE** — One happy-path smoke test exercises the primary user journey. _Here: one agent taken from creation to done through the documented interface._
- [ ] **G1-CI** — The full test suite runs in CI on every pull request and is required to merge.
- [ ] 3 of 6 requirements carry an `@req` anchor; REQ-001 is the first, at `tests/core/core-runnable.test.ts`.
- [ ] The change can be reverted with one command or one flag.

## 3. Change protocol

| Change | What must happen first |
| --- | --- |
| New behaviour on an agent | Add or amend a requirement in `spec.json`, then write the failing agent test. |
| Changed agent shape or error | Update the contract inventory in 04-contracts.md, then the test that pins it. |
| New dependency or service | ADR in 03-architecture.md: what it replaces, what breaks without it, and what removing it later would cost. |
| Test deletion or weakening | Not allowed as a fix for an agent. Skip it with the requirement id and escalate instead. |
