# Architecture

> Generated by vibecode-like-a-dev v0.3.0 · kind cli · stage production · tier 1 (standard)

## 1. Style decision

**Hexagonal single artifact.** A CLI is a thin adapter over a pure core. Keeping IO at the edges is what makes the commands testable without spawning processes.

- Rejected: microservices — an agent write would need a distributed transaction, and there is no team boundary to gain.
- Rejected: serverless-per-endpoint — the agent lifecycle crosses several calls, and cold starts would be paid by a specification.
- Rejected: framework-shaped folders — they would put the agent rules next to the transport code that is supposed to be the thinnest layer.

## 2. Shape

```text
transport   argv · stdin                    (thin: parses, validates, maps errors)
     │ calls interfaces it does not own
application agent use cases · input checks · transaction boundary
     │ domain types and errors only
domain      core                    (pure: no PostgreSQL + Drizzle (forward-only SQL migrations), no framework)
     ▲ implemented by
adapters    PostgreSQL + Drizzle (forward-only SQL migrations) · http clients

Imports point downward only. Anything pointing back up is a bug in Vibecode Like A Dev, not a shortcut.
```

## 3. Modules and import rules

| Module | Responsibility | May import | Must not import |
| --- | --- | --- | --- |
| Core | the product's central aggregate (name it) | its own agent rules only | web framework, database driver, vendor SDK |
| Infrastructure / adapters | PostgreSQL, http clients | every context's interfaces for agent | the agent rules of any context |

## 4. Stack

| Layer | Choice | Rationale |
| --- | --- | --- |
| language | TypeScript (strict) | Fewer moving parts means fewer invented abstractions. |
| runtime | Node.js 22 LTS | Fewer moving parts means fewer invented abstractions. |
| ui | React + Vite (only if a UI is in scope) | Fewer moving parts means fewer invented abstractions. |
| http | Hono or Fastify, typed handlers | Fewer moving parts means fewer invented abstractions. |
| db | PostgreSQL + Drizzle (forward-only SQL migrations) | Boring and relational beats novel and eventual for a first version. |
| validation | Zod at every boundary (input, env, external API) | Fewer moving parts means fewer invented abstractions. |
| tests | Vitest for unit and integration, Playwright for the primary journey | Fast feedback for logic, one slow test for the journey. |
| lint | ESLint + Prettier, typecheck in CI | Fewer moving parts means fewer invented abstractions. |
| logs | pino with a correlation ID field | Fewer moving parts means fewer invented abstractions. |
| ci | GitHub Actions | Fewer moving parts means fewer invented abstractions. |

This is the default. Override it only through an ADR that names the trade-off; the tests and gates do not depend on any specific framework.

## 5. Cross-cutting decisions

| Concern | Decision | Where it lives |
| --- | --- | --- |
| Configuration | Validated at startup against Zod at every boundary (input, env, external API); a missing value fails fast and is named | `config` module, one schema |
| Errors | Typed domain errors mapped to the envelope in `04-contracts.md`; internals never leak | `errors` module + transport mapper |
| Logging | Structured, with correlation and actor id on every line | `observability` module |
| Time and IDs | Injected clock; opaque sortable ids | shared kernel |

## 6. The primary journey, in order

Written for **REQ-001 Runnable from a clean clone** — the first requirement, and the one whose shape the rest copy.

1. Transport receives the request and validates it against a schema.
2. The actor, if any, is resolved and attached to the request context.
3. The application layer loads the agent, checks policy, and calls one domain operation.
4. The domain operation enforces the invariants in `02-domain-model.md` and returns a result or a typed error.
5. The adapter writes to PostgreSQL in one transaction and emits any domain event after commit.
6. Transport maps the result to the contract shape in `04-contracts.md`, including the correlation id.

## 7. Decision records

Non-functional targets for Vibecode Like A Dev go here too: latency on the agent write path, availability, recovery time. A number with no measurement method is a slogan, so write "not measured in v1" instead of pretending.

**ADR-001 — Architecture: Hexagonal single artifact**
A CLI is a thin adapter over a pure core. Keeping IO at the edges is what makes the commands testable without spawning processes. _Consequence:_ Boundaries are checked by an import rule in CI, not by review.

Add an ADR for every dependency around an agent that would take more than a day to remove, and for every boundary decision a future reader would otherwise reverse-engineer from this repository.

## 9. Fitness functions

Architecture that is not executable is decoration, so each of these runs in CI for Vibecode Like A Dev rather than living in a review checklist.

| Property | Check | Automated how | Fails when |
| --- | --- | --- | --- |
| Domain purity | No framework, database driver or vendor SDK imported under `domain/` | import-boundary rule in CI | A domain file imports infrastructure |
| Module boundaries | The 1 contexts import only their own domain and the shared kernel | import-boundary rule | A cross-context import appears |
| Contract agreement | Implementation matches the shapes in 04-contracts.md | contract test | A response field is added or removed silently |
| Requirement coverage | 3 anchored requirements have a passing test | `node specs/spec-check.mjs` | A test is deleted or renamed |
| Assertion density | Every test asserts an outcome, not just absence of a throw | review | A test would pass if the behaviour were wrong |

## 10. When this architecture should change

- A single agent operation needs to scale on a different curve from the rest, measured rather than predicted.
- A agent write starts spanning more than two of the 1 contexts and cannot be made eventually consistent without rewriting the rules.
- The tests for agent rules need PostgreSQL running to pass: that is a broken boundary, not a reason to add a service.
